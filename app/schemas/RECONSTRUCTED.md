Schemas 1–6 were reconstructed from the KSP-exported version 7 schema and the
unchanged migration SQL in HabitudeDatabase.kt. No original schema exports or
identity hashes for these versions were available.

Working backwards, version 6 removes notes; version 5 also removes day_counts
and habits.dailyTarget; version 4 removes habits.weeklyTarget; version 3 removes
habits.archived; version 2 removes past_schedules; version 1 removes
habits.reminderMinutes. Both the field definitions and CREATE TABLE SQL were
adjusted. All other table definitions, foreign keys, indices and primary keys
are preserved. Version 1 habits therefore has exactly id, name, emoji, type,
scheduleMask and createdOnEpochDay, alongside the entries table.

The distinct 32-hex identity hashes in versions 1–6 (and their matching
setupQueries) are placeholders for migration fixtures, not the real historical
Room hashes. Version 7 and its hash are generated by Room. These fixtures test
the historical table shapes and migration SQL; they cannot establish the
original identity hashes.
